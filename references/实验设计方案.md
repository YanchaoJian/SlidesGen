### 2.2 系统健壮性指标

自动化采集，直接从系统日志中提取。

| 指标名称 | 定义 | 计算方式 | 来源参考 |
|----------|------|----------|----------|
| **SVG 生成通过率（SR）** | 首次生成可执行 SVG 的页面比例 | 成功页数 / 总页数 | PPTAgent |
| **自愈修复成功率** | 触发重试后最终修复成功的比例 | 修复成功次数 / 触发重试总次数 | 本系统特有 |
| **端到端生成耗时（s）** | PDF 输入到 .pptx 输出的总时间 | 系统日志计时 | 任务书指标 |
| **平均重试轮次** | 每页平均触发自愈的次数 | 总重试次数 / 总页数 | 本系统特有 |
| **API 调用总 Token 数** | 单次端到端运行的 token 消耗量 | GPT-4o 计费日志 | 效率分析 |
| **DrawingML 转换成功率** | SVG → PPTX 格式转换成功比例 | 转换成功页数 / 总页数 | 本系统特有 |

> **采集方式：** 在 LangGraph 各节点出口处记录时间戳与状态码，运行结束后解析 `checkpoints.sqlite` 中的节点状态，自动计算各项指标。

### 2.3 生成质量指标（LLM-as-Judge）

#### 2.3.1 PPTEval

直接复用 PPTAgent GitHub 仓库（`https://github.com/icip-cas/PPTAgent`）中的评估代码，使用 GPT-4o 作为裁判模型，对三个维度分别打分（1–5 分）：

| 维度 | 评估内容 | 人类相关性 |
|------|----------|------------|
| **Content（内容覆盖）** | 内容准确性与对原文的相关性 | Pearson r = 0.71 |
| **Design（视觉设计）** | 视觉吸引力、色彩和谐度、可读性 | Fleiss' Kappa ≈ 0.59 |
| **Coherence（连贯性）** | 幻灯片间的逻辑流与结构一致性 | — |

> **注意事项：** PPTEval 采用实例无关（instance-agnostic）的评分标准，PresentBench (2026) 指出其与人类偏好的 Spearman 相关系数为 0.303，属于可接受范围但有局限性。建议在论文中客观说明，并通过第三层人工评估进行补充验证。

#### 2.3.2 SlidesBench 无参考设计质量评分

调用 AutoPresent 仓库（`https://github.com/para-lost/AutoPresent`）中的 `reference_free_eval.py`，基于设计原则对生成幻灯片进行无参考评分（0–5 分），涵盖：

- **Content**：内容完整性与信息密度
- **Formatting**：文字排版规范性
- **Overall**：整体呈现质量

```bash
python reference_free_eval.py \
    --image_path path/to/generated_slide.jpg
```

#### 2.3.3 风格一致性得分（本系统专属）

针对本系统引入参考风格图的核心特性，设计定量风格一致性评估（仅用于消融实验，验证风格提取模块的贡献）：

**（1）颜色直方图相似度**

计算生成幻灯片图像与参考风格图在 HSV 色彩空间的直方图相关系数：

```python
import cv2
import numpy as np

def color_hist_similarity(img1_path, img2_path):
    img1 = cv2.imread(img1_path)
    img2 = cv2.imread(img2_path)
    hsv1 = cv2.cvtColor(img1, cv2.COLOR_BGR2HSV)
    hsv2 = cv2.cvtColor(img2, cv2.COLOR_BGR2HSV)
    hist1 = cv2.calcHist([hsv1], [0, 1], None, [50, 60], [0, 180, 0, 256])
    hist2 = cv2.calcHist([hsv2], [0, 1], None, [50, 60], [0, 180, 0, 256])
    return cv2.compareHist(
        cv2.normalize(hist1, hist1).flatten(),
        cv2.normalize(hist2, hist2).flatten(),
        cv2.HISTCMP_CORREL
    )
```

**（2）字体规范匹配率**

解析 .pptx 文件中实际使用的字体列表，与 `style_protocol.json` 中的字体规范进行匹配：

```python
from pptx import Presentation
import json

def font_match_rate(pptx_path, protocol_path):
    prs = Presentation(pptx_path)
    with open(protocol_path) as f:
        protocol = json.load(f)
    required_fonts = set(protocol['typography']['fonts'])
    actual_fonts = set()
    for slide in prs.slides:
        for shape in slide.shapes:
            if shape.has_text_frame:
                for para in shape.text_frame.paragraphs:
                    for run in para.runs:
                        if run.font.name:
                            actual_fonts.add(run.font.name)
    if not required_fonts:
        return 1.0
    return len(required_fonts & actual_fonts) / len(required_fonts)
```

**（3）CLIP 视觉相似度**

使用 CLIP-ViT 模型计算生成幻灯片与参考风格图的嵌入余弦相似度：

```python
import torch
import clip
from PIL import Image

device = "cuda" if torch.cuda.is_available() else "cpu"
model, preprocess = clip.load("ViT-B/32", device=device)

def clip_similarity(img1_path, img2_path):
    img1 = preprocess(Image.open(img1_path)).unsqueeze(0).to(device)
    img2 = preprocess(Image.open(img2_path)).unsqueeze(0).to(device)
    with torch.no_grad():
        feat1 = model.encode_image(img1)
        feat2 = model.encode_image(img2)
    feat1 /= feat1.norm(dim=-1, keepdim=True)
    feat2 /= feat2.norm(dim=-1, keepdim=True)
    return (feat1 @ feat2.T).item()
```

### 2.4 人工感知评估

#### 2.4.1 评估设置

- **评估者：** 5 名具备一定学术背景的研究生（非本项目参与者）
- **评估方式：** 盲评（不告知生成系统名称），每人对 6 × 3 = 18 份幻灯片打分
- **评分量表：** 5 分李克特量表（1=很差，5=很好）

#### 2.4.2 评估维度（5 个）

| 维度 | 题目示例 | 适用系统 |
|------|----------|----------|
| **视觉美观度** | 这份幻灯片在视觉上吸引人吗？ | 全部 |
| **内容忠实度** | 幻灯片是否准确反映了原论文的核心内容？ | 全部 |
| **结构逻辑性** | 幻灯片的页面顺序和叙述逻辑是否清晰连贯？ | 全部 |
| **风格匹配程度** | 生成幻灯片与参考风格图的视觉风格是否一致？ | 本系统（参考 Full vs 消融） |
| **整体可用性** | 这份幻灯片是否可以直接用于学术汇报？ | 全部 |

#### 2.4.3 统计分析

```
评估者间一致性：Fleiss' Kappa
自动指标 vs 人工评分相关性：Pearson r + Spearman ρ
系统间显著性检验：Wilcoxon 秩和检验（非参数，适合小样本）
```

> **参考基准：** PPTAgent 报告 Fleiss' Kappa 平均值为 0.59（可接受）。PresentBench (2026) 与人类偏好的 Spearman ρ = 0.532。本实验若能达到 ρ > 0.5，则自动评估具备充分可信度。

## 四、消融实验设计（4 组）

在原有 3 个消融配置基础上，新增第 4 组"去除自愈闭环"。

### 4.1 消融配置

| 配置 | 描述 | 验证目标 |
|------|------|----------|
| **Full（完整系统）** | 所有模块启用 | 基准性能 |
| **w/o SVG** | 去除 SVG 中间表示，直接生成 DrawingML | 验证 SVG 作为解耦中间层的价值 |
| **w/o CRAP** | 去除 `svg_optimizer` 节点 | 验证 CRAP 设计原则约束的贡献 |
| **w/o HITL** | 跳过大纲审查和成品审查中断点 | 验证人机交互对最终质量的提升作用 |
| **w/o Self-heal（新增）** | 仅保留每页首次生成结果，禁用视觉审查重试 | 验证"代码执行→视觉审查→自动修正"闭环的价值 |

### 4.2 实施方式

- `w/o SVG`：修改 `slide_composer` 节点，直接输出 DrawingML XML，跳过 SVG 渲染步骤
- `w/o CRAP`：注释 `svg_optimizer` 节点的调用，直接将 SVG 传递至执行步骤
- `w/o HITL`：在 `review_plan` 和 `review_pptx_design` 节点中设置自动通过逻辑
- `w/o Self-heal`：将 `slide_reviewer` 节点的最大重试次数设为 0

### 4.3 消融实验评估指标

消融实验重点关注以下指标的变化量（Δ = 变体得分 − Full 得分）：

- PPTEval-Design（CRAP 优化效果主要体现在设计维度）
- 风格一致性得分（HITL 和 SVG 中间层的效果）
- SVG 生成通过率（自愈闭环的核心贡献）
- 端到端耗时（各模块的时间开销）

## 五、效率分析（新增章节）

### 5.1 成本构成分解

在实验采集阶段，对每次运行记录各节点的 Token 消耗和耗时：

| 节点 | 模态 | 预计 Token 占比 |
|------|------|----------------|
| 语义增强（semantic_enhance） | 文本 | ~10% |
| 风格提取（analyze_image_style） | 视觉 | ~8% |
| 大纲规划（generate_presentation_plan） | 文本 | ~5% |
| 布局指令（slide_planner × N页） | 文本 | ~15% |
| SVG 生成（slide_composer × N页） | 文本 | ~30% |
| CRAP 优化（svg_optimizer × N页） | 文本 | ~10% |
| 视觉审查（slide_reviewer × N页 × 重试） | 视觉 | ~22% |

### 5.2 成本-质量权衡说明

在论文中客观分析以下两点：

1. **10 页以内性能目标**：记录实际耗时数据，与任务书"10 页以内不超过 5 分钟"的目标进行对比，说明差距及原因（视觉审查重试是主要瓶颈）。

2. **优化方向**：提出 3 条可行的降本路径作为未来工作：
   - 将视觉审查模型替换为更轻量的专用评估模型
   - 对不同复杂度的页面动态调整最大重试次数
   - 引入批处理 API（Batch API）降低单次调用成本
